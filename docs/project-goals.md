# North Star

Teach developers how to build a citizen-focused AI application with country-specific Nemotron Personas and the NVIDIA NeMo stack. Singapore learning and community activities are the concrete example. The developer must see the whole system, demonstrate it through the UI, and trace each behaviour to integration code, configuration and native evidence.

## Agreed v0.2 requirements

- Carry one recognisable citizen story through simulation, tools, routing, tracing, evaluation and deployment. Inspecting saved evidence never starts inference. Explain the purpose of every additional comparison or repeated trial.
- Keep the UI, CLI and developer MCP surfaces on shared application services. The advisor's runtime tools remain limited to the read-only course catalogue.
- Integrate Singapore Nemotron Personas, UserSim, Data Designer, Relay, Fabric, Switchyard with LiteLLM, Helix and behavioural Guardrails. Demonstrate both LangChain Deep Agents and Hermes harnesses. Wrap agent execution and its course tools in OpenShell.
- Use LiteLLM as the configurable model proxy for hosted NIM, Brev OpenAI-compatible endpoints and frontier APIs. Show actual Switchyard decisions; comparisons of harnesses use a fixed model.
- Support actual Helix Platform registration/deployment, with a local reference and an existing-remote-Platform connection profile. Model hosting is independent of Platform hosting.
- Provide an interactive data workbench for public HF Singapore personas and **NGC Singapore Nemotron Personas Extended only**. Do not expand this into a general NGC catalogue browser.
- Sample from the full available audited corpus; preview, reshuffle, lock and replay exact records. Three age groups are diagnostic coverage, not three persona types.
- Demonstrate genuine source-seeded Data Designer scenarios, user-defined columns (including hypothetical gross monthly salary in SGD and favourite brands) and additional synthetic rows. Keep originals, overlays and generated profiles distinct with hashes and lineage.
- Show source profiles, scenario assumptions, UserSim activations, MCP requests/results, native Relay scopes, Fabric lifecycle, model routing, row-level Helix criteria, local artifacts and integration source locations.
- Preserve failures and warnings. Transport completion does not prove a valid answer. Empty answers, provider error strings and malformed pseudo-tool output must not receive a successful evaluation.
- Maintain dated official course snapshots and honest no-match handling. Profiles and synthetic salary/brand hypotheses do not establish citizenship, funding eligibility, real demand or observed behaviour.
- Keep credentials, raw data, generated rows, conversations and trace payloads out of Git. Bound model calls and preserve unknown usage.
- Migrate documentation together; retain v0.1 as historical evidence rather than relabelling its results as v0.2 verification.

## Decision rule

Prefer the implementation that makes a working application behaviour and its real evidence easiest for a developer to understand. Do not add a product badge or mock success in place of an integration. Label unavailable, offline, recorded, live and unverified capabilities explicitly.
