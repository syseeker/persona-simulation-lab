## Four tabs, one selected story

**Why NeMo Stack** explains the application’s purpose, the developer painpoints and each component’s contribution. **Integration Map** connects internal modules with labelled information flows. **Q&A** explains the boundaries and links back to the map. **Datasets → Data schema** preserves the dated audit comparison, with readable field labels grouped as names/identity, personal details, location, education/work, skills/interests, narratives and OCEAN.

Open **Datasets → Explore profiles** to read a bounded page from either installed original distribution. Choose HF public or NGC Extended, enter text and optional age, area and education constraints, then **Apply filters**. Source-wide option counts remain distinct from the matching result count. **Clear filters** restores that distribution. Select a profile to inspect its original fields, source revision, row hash and NGC trait JSON; the HF source has no names or OCEAN fields to invent. Paging and filtering make zero inference calls. Filters and the chosen subtab persist locally; raw rows are not saved in browser preferences or bundled into the guide. Missing data or a disconnected reader shows an explicit error with access to the schema reference.

The default is **Trace a Request → Find a photography class → Step 1 of 9**. Choose one scenario; its persona, harness and baseline model are preset context. Collapse **Scenario summary** to focus on the walkthrough; the single scenario dropdown stays visible. There are no independent configuration pickers to combine into a product matrix.

The nine lessons navigate one architecture. **Simplified** separates test person, test situation, simulated learner, citizen advisor, course information, model access and execution records/checks. **Detailed** expands those responsibilities into the important library operations; safeguards and operational boundaries remain distinct. Entering the map, switching views or resetting layout shows everything without dimming. **Follow this step on the map**, Back/Next/Play or selecting an operation focuses its participants and directional flows.

The right panel answers **Why this matters → In this scenario → How it works → Check your implementation**. Select a block or operation without losing lesson position. Detailed operation entries show ownership, inputs, configuration, outputs and checks, followed by **Application call · Configuration · Scenario log · Library architecture**. Code links target an allowlisted symbol at the current committed repository revision; hash comparisons distinguish matching recorded source, different recorded bytes and uncaptured references. Log links target this exact scenario/run and file. There are no snippets, raw JSON previews or all-file dumps. Raw private-run APIs remain compatible; future live-log presentation is deferred. Playback and inspection never start inference.

Its three authored public turns introduce the learning goal, voluntarily disclose a hypothetical salary band, then state an explicit training budget and study constraints.

The S$2,500–3,499 gross monthly salary band belongs to private simulator context until turn 2. A S$3,000 budget, weekend availability and preference for shorter options arrive in turn 3. The approximately six-month/S$20,000 programme is hypothetical. Do not treat it as a provider listing, infer affordability from salary or promise employment or earnings. The current wireframe illustrates these fields and routing responsibilities; it has not generated them through Designer or produced an actual Switchyard decision.
